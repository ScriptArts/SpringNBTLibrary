# 0010. 26.3のパレット形式に合わせて対応の下限を上げる

- 状態: 採用（[0011](0011-format-eras.md)で一部を置き換え）
- 日付: 2026-11-19

## 背景

Java版26.3（DataVersion 5023）で、チャンクのブロックのパレットの形式が変わった。
Minecraftがこの形式へ変換するDataVersionは`5006`で、26.3 Snapshot 7で入った。

- 既定の状態のブロックはブロックIDだけの文字列で保存される
- それ以外のブロックは、`Name` / `Properties`が`id` / `properties`に改名された
- 文字列とCompoundが混ざったパレットは異種リストとして保存される。Compoundのリストになり、文字列は`{"": <値>}`に包まれる

1.0.1で26.3のワールドを読むと、パレットの要素が文字列のところで`UNEXPECTED_TAG_TYPE`になる。
NBTとしては読めるので、Anvilレイヤまでの走査では見つからなかった。

## 決定

1. `MIN_SUPPORTED_DATA_VERSION`を`5006`へ、`TARGET_DATA_VERSION`を`5023`へ上げる。26.2までの形式は扱わない
2. パレットの要素は文字列・`{id, properties}`・`{"": <値>}`の包みを読む。`id`の無いCompoundは`MALFORMED_DATA`にする
3. 書き出しは、プロパティが空なら文字列、それ以外は`{id, properties}`にする。Minecraftと同じ形である
4. 包みの付け外しは`PalettedContainer`で行う。読むときに外し、書くときに要素の型を見て包み直す。NBTレイヤは包みを扱わない
5. 文字列の要素は、プロパティが空の`BlockState`として読む。ブロックごとの既定値は持たない

## 理由

- 1: 古い形式も扱うと、パレットの読み書きがMinecraftのバージョンによって2通りになる。5言語すべてに分岐とテストが要るうえ、書き出す形式を取り違えればワールドを壊す。
  [0003](0003-version-policy.md)のとおり、形式が変わったら下限を上げる
- 4: [0006](0006-snbt-scope.md)でNBTレイヤが包みを扱わないと決めたのは、利用者が書いた`{"": <値>}`と包みを区別できないからである。
  パレットの要素は文字列か`id`を持つCompoundに限られるので、パレットに限れば包みと見分けられる。
  付け外しの規則はMinecraftの`ListTag`と同じにして、触っていないパレットは元とバイト単位で一致させる
- 5: 既定値を知るにはブロックの定義一覧が要る。定義はMinecraftのバージョンごとに変わるもので、データ形式のライブラリが持つものではない（[0004](0004-defer-heightmap-recalc.md)と同じ理由）

## 結果として受け入れること

- 26.1 / 26.2のワールドは扱えなくなる。バージョン番号のいちばん上の桁を上げる
- 26.2で作ったワールドを26.3で開いても、読み込まれなかったチャンクは古い形式のまま残る。
  そうしたチャンクは読み込み時に警告が出て、ブロックを読むと`MALFORMED_DATA`になる。
  ゲームの「ワールドを最適化」ですべてのチャンクを変換してから使う
- 文字列で読んだブロックは、プロパティが空になる。
  `minecraft:oak_stairs`と、既定値をすべて書いた`minecraft:oak_stairs[facing=north,half=bottom,shape=straight,waterlogged=false]`は等しくない。
  後者を置くと、同じ状態を指す要素がパレットに2つ並ぶことがあり、`compact()`でもまとまらない

## 追記（2026-11-20）

決定1（26.2までの形式を扱わない）は、[0011](0011-format-eras.md)で置き換えた。
26.2までの形式は1.18〜26.2の世代（C4）として、`{Name, Properties}`のまま読み書きする。
決定2〜5は26.3以降の世代（C5）の決め事として残す。
